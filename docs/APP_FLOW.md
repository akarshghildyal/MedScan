# MedScan Application Flow & Screens Guide

This document explains the user experience, screens, and interactions within the MedScan application. MedScan is designed to simplify medical reports for patients while providing actionable clinical data for doctors, all powered by an advanced multi-agent AI backend.

---

## 1. User Roles & Authentication

The application supports different user roles, each with a distinct experience and access level:

- **Patient**: The primary user who uploads their medical reports (PDFs), views AI-simplified summaries, tracks biomarker trends, and actively shares their data with doctors.
- **Doctor**: A medical professional who reviews reports shared by patients. They get a clinical-focused view of the analysis.
- **Dev/Admin**: Used for testing and debugging the AI pipeline and raw backend data.

### Authentication Flow (Login & Registration)
- **Content**: 
  - Login requires Email and Password.
  - Registration requires Full Name, Email, Password, Biological Sex, and Date of Birth.
- **Interaction**: 
  - Unauthenticated users attempting to access dashboard routes are redirected back to the `/login` page.
  - Upon successful login, the `App` router checks the user's role and automatically redirects them to their designated home screen (`/patient`, `/doctor`, or `/dev`).

## 2. Patient Dashboard (`/patient`)

The Patient Dashboard is the core interface for individuals to manage their medical history.

### Screen Content
1. **Health Overview Card**: Greets the patient and shows a quick statistic on how many reports they have in their history.
2. **Quick Upload Card**: A prominent button prompting the user to upload a new pathology report (PDF format).
3. **Report History Table**: A chronological list of all reports uploaded by the patient.
   - **Columns**: Filename (with a snippet of the AI summary), Report Type (e.g., CBC), Date Uploaded, Status, and Actions.
   - **Status Badges**: Shows if the report is `PROCESSING`, `ANALYZED`, or `FAILED`.

### Interactions & Modals
From the Patient Dashboard, users can trigger several key interactive modals:

#### A. File Upload Modal
- **Trigger**: Clicking the "Upload New Report" card.
- **Content**: A drag-and-drop zone for PDF files.
- **Interaction**: When a file is selected, it uploads to the backend. The backend immediately kicks off the 7-step Agentic Pipeline (parsing, classifying, data extraction, abnormality detection, insight generation, and summarization). The dashboard polls for the status until it turns green (`ANALYZED`).

#### B. Report Analysis Modal
- **Trigger**: Clicking the "View" button on an analyzed report in the table.
- **Content**:
  - **AI Summary**: A patient-friendly, high-level summary of the report.
  - **Detailed Explanation**: A deeper, plain-English breakdown of normal vs. abnormal findings.
  - **Key Clinical Insights**: A highlighted panel containing bulleted warnings or notable observations generated by the AI.
  - **Extracted Values Table**: A list of all identified biomarkers (e.g., Hemoglobin, Glucose), showing the extracted value, unit, reference range, and a color-coded Status Badge (`NORMAL`, `LOW`, `HIGH`, `CRITICAL`).

#### C. Trend Visualization Modal
- **Trigger**: Clicking the small "Chart" icon next to any numeric marker in the Extracted Values Table.
- **Content**: A Plotly.js interactive graph showing the historical trend of that specific biomarker across all past reports.
- **Interaction**: Users can hover over data points to see exact values and dates, helping track progress over time.

#### D. Contextual Chatbot Modal
- **Trigger**: Clicking the "Chat" icon on a report in the History Table.
- **Content**: A messaging interface titled "MedScan Medical Assistant".
- **Interaction**: The patient can type questions specific to that report (e.g., "What does it mean that my WBC is high?"). The AI responds using the specific context, numbers, and insights from *that exact report*, while safely advising them to consult a doctor for diagnosis.

#### E. Share Report Modal
- **Trigger**: Clicking the "Share" icon on a report in the History Table.
- **Content**: An input field requesting a Doctor's ID.
- **Interaction**: Submitting the ID securely grants that specific doctor read-access to the report through the backend sharing API.

## 3. Doctor Dashboard (`/doctor`)

The Doctor Dashboard is a streamlined interface designed for medical professionals to review reports that patients have explicitly shared with them.

### Screen Content
1. **Overview**: A greeting indicating how many shared reports require review.
2. **Shared Reports Table**: Lists the reports shared by patients.
   - **Columns**: Patient ID/Name, Report Type, Upload Date, and Actions.

### Interactions & Modals
#### A. Clinical Review Modal
- **Trigger**: Clicking "View Details" on a shared report.
- **Content & Interaction**: Similar to the Patient's Report Analysis Modal, but serves a clinical purpose. The doctor can instantly view the AI's Extracted Values, Status Badges, and Key Clinical Insights without having to read through dense, raw PDF text. They can also access the Trend Visualization for that patient's markers to make rapid, informed clinical decisions.

---

## 4. Developer Dashboard (`/dev`)

A testing interface for engineers to monitor the AI pipeline's raw output.

### Screen Content & Interaction
- Contains a File Uploader and a History Table.
- When "View Raw JSON" is clicked, it opens a modal containing a **JSON Tree View** component.
- This allows developers to inspect the exact structured data payload returned by the 7-agent pipeline, including the arrays of `markers` and `insights`, ensuring the backend data models are behaving correctly.

---

## Summary of Data Flow

1. **Upload**: User PDF -> React Frontend -> FastAPI Backend (`/reports/upload`).
2. **Pipeline**: Backend spins up background tasks -> 7 AI Agents extract, analyze, and summarize -> Saves to MongoDB Document.
3. **Retrieval**: React Dashboard polls `/reports/` -> Fetches analyzed document.
4. **Interaction**: Patient reads summaries, asks questions via Chat API, and visualizes trends via Trends API.
5. **Collaboration**: Patient shares Report ID & Doctor ID to backend -> Doctor logs in -> Dashboard fetches shared documents via `/doctor/reports`.
